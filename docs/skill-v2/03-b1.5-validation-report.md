## 2. A — ShapeTags (M16)

- **The discrepancy:** M16 states two rules for `compact`. One is `cells / bbox area ≥ 0.75`. The other is a table
  listing only `square` and `p5`. Applied literally, the ratio rule also tags `mono`, every bar (fill 1.0), `l3`
  (0.75) and `u5` (0.83), so the two statements contradict each other.
- **Resolution:** `compact` = fill ≥ `COMPACT_MIN_FILL` (0.75) **and** the piece holds a full 2×2 block. Both
  statements of M16 now hold.
  - The library result is exactly `[p5, square]`.
  - An Odd blob with a 2×2 but a fill below 0.75 (e.g. 7/12) is not compact.
- **Related fixes:**
  - The tag `P` is limited to 5-cell pieces (`p5`). Before this, an Odd 2×3 rectangle was tagged `P`.
  - `centre` ties now go to the cell nearest the hero, as M16 says. Before this they went to smallest y, then x.
  - New output field `fill`.
- **Gameplay effect:** none. No card reads tags yet.
- **Open M16 item:** the `shape_tags.json` data table (keyed by canonical key) is not created. Computed tags stand in
  for it, and the test pins the library table. The extra tag `domino` (bar2) is kept; nothing uses it.

## 3. B — CastContext

- **New fields:**
  - `schema` (2), `caster_side` (alias of `side`)
  - `t_cast` (the arbiter clock at the cast), `cast_mode`
  - `effective_cells`: the damage cell count after the signature cell rule, e.g. Trảm ×2, read at cast time
  - `featured_bonus`: the full bonus details, deep-copied
  - per piece: `canonical_key`
- **Backward compatibility:** `build()` takes an optional `extras`. Old callers get the defaults: `direct`,
  `effective_cells = cell_count`, `{}`, `0.0`.
- **Snapshot safety:**
  - `SwingArbiter` freezes the context when the swing resolves (`CastContext.freeze` makes it read-only deeply).
  - Every wave, event and listener receives the **same** frozen instance.
  - The caller's dictionary is untouched (CutActor stores a deep copy).
  - A `duplicate(true)` of the snapshot is writable.

## 4. C — CastResolver and the scheduler

- **`CastResolver.validate`**
  - Accepted resolve modes: `instant`, `waves`, `arrival`.
  - Checked fields:
    - `hits` and `max_hits`: whole numbers 1–8
    - `hit_interval_sec`: 0.02–2.0
    - `wave_mults`: numbers ≥ 0
    - `instant` with hits > 1 is rejected
  - B1.5 limits scheduled modes to `effect: damage` and `cast_mode: direct`.
  - Any error is pushed as an error and listed in `SkillConfig.validation_errors`, and the card falls back to its
    legacy `instant` path. Unknown modes are never silently treated as instant. The real `cards.json` has 0 errors.
- **`CastResolver.plan`** returns `{resolve, legacy, max_hits, waves, events}`. Events are sorted by
  (t, wave, y, x) and indexed. The three modes:
  - `instant`: one event, all cells, t = 0. All 32 cards use it, and the arbiter runs its unchanged pre-v2 code for
    it.
  - `waves`: `hits` waves, `hit_interval_sec` apart, optional `wave_mults` (M08 engine form).
  - `arrival`: one event per cell at `SkillDelivery.arrival_times`, the same timing table as the visuals. It is one
    wave for projectile, ground and chain deliveries, and one wave per cell for `SKY_TO_TARGET` (M05).
- **`SwingArbiter`**
  - **Clock:** an authoritative `clock()`. A tick slice never jumps over a pending event. At the same instant, swings
    settle first, then due events fire in (time, schedule sequence) order. Different tick sizes give the same log
    (tested).
  - **Hit rules:** an event hits only if the target stands on its cells *at that moment*, at most once per wave and
    at most `max_hits` per cast. Damage counts the cast's total (unlocked) cells (new `CutEffects` option
    `cast_cell_count`). A wave multiplier is applied through `impact_mult`. Heal-self happens once per cast.
  - **Interruption:**
    - Only the first damaging event interrupts the opponent's swing; not on a t = 0 trade, never for a parry card.
    - A caster interrupted before its swing resolves schedules nothing.
    - Once resolved, the cast's events survive the caster being hit.
  - **Cleanup:** a unit's death clears every event. `clear_scheduled(side)` exists for the match end. Cleared casts
    emit nothing more.
  - **Signals:**
    - `impact_resolved(side, event, hit)` per event and `wave_resolved` per wave.
    - One `swing_resolved` per cast when its last event fires (hit = any, damage = sum, `scheduled: true`), so
      card-level listeners see one outcome per cast.

## 5. D — Regression investigation

### PLACE FAIL (Assassin vs Mistbriar Matron, B1 matrix, t = 132.9)

- **Verdict:** a bot limitation, not a gameplay defect.
- **Evidence:**
  - The log line reads `sel false … piece t4 placed false menu false swing false`, so `CombatView.select_piece`
    refused.
  - Its refusal paths are: no hold (impossible, the line read the hold), menu open (false), joining (not placed),
    an unplaceable piece (t4 is placeable), or a dead unit.
  - The hero was at 144 HP. The match ended `WIN` with the enemy at 0, and `133s` is `%.0f` of 132.9, the same
    frame.
  - So the enemy died *during* the awaited frame, and the bot then acted on a finished match.
- **Reproduction:**
  - The windowed bot is **not deterministic**: the same seed gave 133 s and then 128 s, without the fail.
  - Logs: `botmatrix_b1/sat_thu-mistbriar_matron.log` (B1 run) and `bot_rerun_b15/` (rerun), in the session
    scratchpad.
- **Bot fix (QA tool only, `tools/qa/play_bot.gd`):**
  - It stops on the frame a unit dies.
  - A `PLACE FAIL` line now also prints both units' dead flags and HP.
  - 20 later matches had no `PLACE FAIL`.

|---|---|---|---|---|---|---|---|

- **Conclusion:** the timeouts predate B1. They come from Matron's length against the bot cap, not from B1.
  - They are a balance / bot question, not a regression.

## 7. Remaining limitations

1. **VFX and engraving:** no VFX listens to `impact_resolved` / `wave_resolved` yet, and Engraving does not light
   per event.
2. **Restricted card types:** scheduled modes are limited to direct damage cards. Zone, status and parry cards are
   rejected by validation and stay instant.
3. **Push:** a push card in `waves` would push on every hit; not designed yet.
4. **Not built yet:**
   - `burst_first`, chain `ramp` / `bounce`, `from_centre` order, ground-propagation blockers (M04).
   - Fixed per-hit damage (Ngàn Kiếm).
   - `combo_3` crit.
   - Fuse, trap and echo floor objects (M07, M09, echo).
5. **Featured bonus:** in `waves`, the featured multiplier and featured effect apply on every hit. Per-hit or once
   per cast is a design choice still to make.
6. **Boss brain:** it does not see pending events, so it cannot dodge shadows (M05 needs this).
7. **Hook timing:** card-level hooks fire at the cast's last event. Relic and pattern hooks on a multi-hit card land
   later than the first damage number.
8. **Locked cells:** the cast cell count is fixed when the swing resolves. A cell locked later still counts toward
   damage; its own event cannot hit because CutEffects drops locked cells.
9. **Q10 rule effect:** the approved 0.5 s no-option rule changes the Knight's sim numbers (parry hands are often
   all-unavailable). The win rate is unchanged in the 5-seed sim.

## 8. Readiness for the first advanced skill

- **Verdict:** ready for a direct damage skill that uses `arrival` or `waves`. Not ready for sky drops, fuses, traps
  or wards.
- **Recommended first prototype:** **Trảm Địa** (`tram_dia`, Knight, `CASTER_TO_TARGET`, arrival).
- **Already working for it:**
  - The resolver timeline and per-event hit test.
  - The interruption rule.
  - The frozen context with `line_h` tags.
- **Still needed:**
  - A `burst_first` multiplier on the first event (a small resolver option).
  - The card's Pin on the burst.
  - The `line_h` +15 % per travelled cell clause (cap +45 %).
  - Its VFX subscription.
- **Not first:**
  - **Ngàn Kiếm:** needs fixed per-hit damage, `from_centre` order, a shadow telegraph and boss awareness.
  - **Hỏa Lôi, Bẫy Kẹp, Thánh Thuẫn:** need the fuse, trap and ward zone kinds.
